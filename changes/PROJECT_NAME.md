# Project name recommendation

## Recommended working name: Quipborough

Recommended public forms:

- Project title: **Quipborough**
- Optional full game title: **Quipborough Online**
- GitHub repository slug: `quipborough`
- Server package description: `Quipborough local client and server`

Why this is a better fit:

- It describes the joke-and-gag tone without retaining the legacy game's
  proper name.
- It does not imply that the project is an operating system.
- It is short, pronounceable, and usable for client, server, launcher, and
  community documentation.

`ToontownOS` is not recommended because it keeps the exact legacy game name
that this fork is trying to neutralize, and the `OS` suffix normally suggests
an operating system rather than a game/client-server project.

`Jestertown` was considered but rejected after the final collision check
because it was already the name of a clown-themed scare zone at
[California's Great America Halloween Haunt](https://www.westcoaster.net/home/2017/11/20/californias-great-america-halloween-haunt-2017-scare-zones-and-shows).

`ToonForge` was rejected because [ToonForge is already an active
product](https://toonforge.app/). `OpenTown` remains the current local build
name, but
[OpenTown is also used by an existing metaverse product](https://partechpartners.com/companies/mindlogic)
and is less distinctive.

No executable, Python package, protocol identifier, database field, or
resource path has been renamed to Quipborough yet. A repo-wide rename should
only happen after the maintainer explicitly chooses the final name, because
those changes affect release filenames, documentation, configuration, and
compatibility-sensitive paths.

An exact-name web and GitHub search did not surface an existing Quipborough
game or repository on 2026-07-25. That limited search is not exhaustive and
is not trademark, domain, or legal clearance.

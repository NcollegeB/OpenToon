# Changes made on 2026-07-26

This log records the first P0 implementation pass after the 2026-07-25
feature audit. It distinguishes source and focused-test coverage from live
client validation.

  - live accounts, avatar YAML, logs, generated world state, and backups;
  - launcher build tools, work directories, and compiled output; and

  Windows batch and PowerShell entry points use CRLF.
- Added tracked `.gitignore` placeholders for generated game data, client logs,

  sibling runtime.
- Updated `launcher/build_windows.ps1` to accept
  `OPEN_TOONTOWN_BUILD_PYTHON`, use `python` from `PATH`, or accept the
  existing explicit `-PythonExecutable` argument.
- Replaced the stale nested `game/README.md` with a short OpenToon game-source
  overview that points to the public root setup guide.
- Removed the obsolete personal contact name, phone number, and vendor email
  from the in-game editor metadata without changing editor behavior.
- Removed optional contact-email lines from the four retained Magic Word
  Manager headers while preserving their author, copyright, contributor,

## Authoritative ordinary hood fishing

- Added `game/toontown/ai/FishManagerAI.py` as the authoritative owner of
  fishing-pier occupancy, catch selection, persistent fish collection/tank
  updates, tank sales, fishing trophies, and trophy Laff boosts.
- Wired `FishManagerAI` into `ToontownAIRepository`.
- Replaced the empty fishing-spot discovery stub with recursive pond-DNA spot
  generation and created the configured moving targets for each public hood
  pond.
- Implemented server-side pond, target, and pier behavior:
  - one occupied pier per avatar;
  - participant, zone, health, rod, jellybean, tank-capacity, and cast-range
    validation;
  - one jellybean charge per accepted cast;
  - a pending-cast requirement before a target can award a catch;
  - server reconstruction of the cast landing point and validation of both
    target distance and flight timing;
  - moving target state and expected-position tracking;
  - quest-item, fish, jellybean, and boot results;
  - rod validation for requested fish;
  - persistent fish collection and tank updates; and
  - fish-tank sale value, clearing, trophies, and Laff rewards through the
    existing fisherman path.
- Repaired `FishTank.removeFishAtIndex()` so it removes the requested entry and
  safely rejects negative or out-of-range indexes.
- Repaired the caught-boot item-label call, routed a Bingo boot through the
  existing last-catch path, and clamped negative client target-movement
  intervals to zero.

Ordinary fishing in this pass means the public hood ponds generated from hood
DNA. Estate-pond fishing is not implemented by this pass. Fish Bingo still
lacks authoritative server gameplay and remains follow-up work.

## Trolley-minigame skip lifecycle and policy

- Added `MinigameSkipPolicy.py` as a small shared policy module for active-play
  validation, unanimous voting, and completion-only quest credit.
- Moved the common Skip Minigame button out of rules/pre-play and into active
  `frameworkGame` play.
- Added an explicit Yes/No confirmation and a visible vote-count/status
  display.
- Chose a unanimous policy: every unique current participant must vote before
  the shared game is skipped. Duplicate and nonparticipant requests do not
  advance the vote.
- Retained zero jellybean rewards for an explicit skip.
- Added the `setSkipVoteStatus` distributed field and localized the new
  confirmation and status text.
- Moved play-minigame ToonTask credit out of game creation. Credit is now
  granted once for a normal, non-skipped completion in `gameOver()`, before
  the client-exit barrier. An explicit skip does not count as a completed
  minigame.
- Added cleanup guards for the known early-abort fields in Toon Escape, Maze
  Game, and Treasure Dive.

The lifecycle and vote policies have focused source/logic coverage, but this
pass does not claim an all-16-game live cleanup result or a live multi-client
unanimous-vote result. Those acceptance checks remain open in `TODO.md`.
